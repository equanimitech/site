A principle of the [Sovereignty layer](/notes/start-here). Control is not a single setting. It is the property that any part can be turned off, and the rest still stands. Defaults exist, but they can always be overridden.

**The design test**

> Can the user explain what this tool does and why? Can they disable any feature without breaking the whole?

<details>
<summary>How it shows up in the work</summary>

- **Zenborg**: phases, areas, attitudes, and cycles are all user-configurable. The Night phase can be hidden entirely. No feature is gated behind an account tier.
- **Respost**: the recipient owns whether and when to open. No read receipts, no tracking.
- **Secretariat**: cognition is pluggable. Claude Code, the API, or a local model. The principal owns the brain, not a vendor.

</details>
